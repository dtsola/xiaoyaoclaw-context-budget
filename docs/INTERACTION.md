# 03 · 用户视角交互流程（`context-window-budget`）

> **技能范围**：只做一件事 —— **把「已启用模型」的窗口按 60% 设置**。
> `maxTokens` / 压缩阈值 / 其它参数一律不碰。
> **60% 是技能内部的默认判断，不需要用户知道、更不需要用户说出来。**

---

## 核心：三段式 —— 检测 → 决策 → 执行

```
用户：用一下这个技能（或什么都不用说，技能自己定期跑）
        │
        ├─ ① 检测（全自动）  盘点在用模型 → 去官网取最新窗口 → 比对现状
        │       └─ 无差异 → 一句话结束（到此为止）
        │       └─ 有差异 ↓
        ├─ ② 决策（用户只做一个动作：采纳 / 不采纳 / 看详情）
        │
        └─ ③ 执行（全自动）  备份 → 改配置 → 校验 → 回执 + 撤销入口
```

**用户的全部工作**：看一眼卡，回一个数字。**其余都是技能的活。**

---

## ① 检测（自动，用户不需要提供任何信息）

技能自己完成四件事：

1. **找**：系统里当前"在用"的模型（主力模型 + 图像/PDF 这类旁路模型；没在用的不动）
2. **取**：到各模型**官网**取最新标称窗口（带来源链接 + 抓取时间）
3. **比**：官网标称 vs 本机现值，找出差异
4. **算**：按 60% 算出建议值（用户看不到算式，只看到建议）

**检测的两种出口**

- **出口 A：无差异**（最常见）
  > ✅ 检测完成：2 个在用模型的窗口都合适，无需调整。
  → 结束。**用户什么都不用做。**

- **出口 B：有差异** → 进入 ② 决策

---

## ② 决策（用户唯一的动作）

技能给出一张卡（≤10 行），只说三件事：**哪个模型、官网是多少、建议改成多少**。

> 🎛️ **检测到 1 项可调整**
> · `minimax/MiniMax-M3`（图像）｜ 官网标称 **1,000,000** ｜ 现值 200,000 → 建议 **600,000**
> · `deepseek-flash`（在用）｜ 官网 1,000,000 ｜ 现值 600,000 ✅ 无需调整
> *建议值 = 官网窗口 × 60%（留余量，防注意力分散）*｜来源：两家官方文档（今天抓取）
>
> 回 `1` 采纳 ｜ `2` 保持现状 ｜ `3` 看详情（来源链接、未在用模型）

**用户的选项**
| 回复 | 含义 |
|---|---|
| `1` | 采纳建议（可只采纳其中几项，如 `1` 后跟 `只改 M3`） |
| `2` | 保持现状（技能不做任何改动） |
| `3` | 看详情，看完再决定 |

> 用户**不需要**懂 60% 是什么，也不需要知道压缩阈值、reserve、重启这些词。

---

## ③ 执行（自动）

用户回 `1` 之后，技能自己做完并回执 **3 行**：

> ✅ 已改 1 项：`minimax/M3` 200,000 → **600,000**
> 校验通过（窗口已生效）
> 如需撤销回「撤销」（已自动备份）

**技能在幕后做的**（用户不需要知道）：备份**本次被改字段的旧值** → 改配置 → **提示需要重载/重启（不擅自执行）** → 校验 → 如实回报。

---

## 触发方式（三种，用户都不需要准备）

| 触发 | 谁发起 | 用户看到 |
|---|---|---|
| **用户随口说** | 用户 | 「检查模型窗口」「我换了个模型」→ 进入 ① 检测 |
| **定期自检**（建议每周一次） | 技能 | 无差异 → 静默；有差异 → 只发一条 → 用户回 `1`/`2` |
| **新增/更换模型时** | 技能 | 只针对那个新模型出一张卡 |

**定期自检的消息形态**（有差异才发，无差异一个字不说）：

> 🔔 检测到变化：`MiniMax-M3` 官网窗口从 1,000,000 改为 **2,000,000**
> 现值按 1M 设置（600,000）→ 建议改为 **1,200,000** ｜ 回 `1` 采纳 ｜ `2` 保持

---

## 边界：技能什么时候反过来问用户

| 情形 | 技能会问 |
|---|---|
| 官网取不到标称窗口 | 「这个模型官网没取到，能给我官方链接吗？或回『先跳过』」 |
| 官网值与现值差一个量级 | 「官网标称是现值的 4 倍，确认以官网为准吗？」（防填错） |
| 建议值会导致模型不可用 | 拒绝执行并说明（正常情形不会发生） |

---

## 明确不做（用户 12:02 / 12:04 / 12:11 划定）

- 只做「窗口按 60% 设置」；`maxTokens`、压缩阈值、成本、并发等**一律不碰**
- 60% 是**技能内部默认**，不作为用户输入项（用户不需要知道这条规则）
- 没在用的模型默认不配
- **不留痕、不记录修改历史**（无审计文件、无历史清单）
- 不做"用户自己算"的任何要求

---

## 用户使用流程（全周期时间线）

### 第 0 步 · 启用（一次性）
装好技能即可（ClawHub 安装 / 放进本机技能目录）。**不需要填任何参数** —— 60% 的比例、去哪取官网数据、只配在用模型，都是内置默认。

### 第 1 步 · 首次使用（约 1 分钟，用户操作 1 次）
- **用户说一句**：「看看我的模型窗口配好没」/「我换模型了，把窗口配上」/ `/ctxbudget`
  （不用记命令，说人话即可）
- **技能自动检测**：盘点在用模型 → 抓官网标称 → 比对
  - 都合适 → `✅ 检测完成：模型窗口都合适，无需调整。` → **结束**
  - 有建议 → 出决策卡 → 进下一步
- **用户回一个数字**：`1` 采纳（或 `2` 保持 / `3` 看详情）
- **技能自动执行 + 回执**：改了什么、校验结果、怎么撤销

### 第 2 步 · 日常（用户 0 操作）
技能每周自动检测一次：
- 无变化 → **静默，一个字都不说**
- 有变化 → 一条提示 → 用户回 `1` / `2`

> 一整年下来，绝大多数周用户完全不需要动作。

### 第 3 步 · 新增 / 更换模型（用户 1 句话）
- 用户：「我加了个 kimi，把窗口配上」
- 技能：只针对这个新模型 → 检测 → 一张小卡 → 用户回 `1` → 执行

### 第 4 步 · 需要回退时（用户 1 句话）
- 「撤销上次上下文调整」→ 回滚到改动前的配置 + 校验 + 回执
- **技能不记录历史、不写审计**（用户 12:11 定）：用完即走，不在工作区留痕迹

### 用户全周期操作总量

| 事项 | 用户操作 |
|---|---|
| 首次配置 | 回 **1 个数字** |
| 日常维护 | **0**（只在厂商真的改了窗口时才被问一次） |
| 换/加模型 | 回 **1 个数字** |
| 回退 | 回 **1 句话** |

**用户永远不需要**：知道 60% 这条规则、知道 reserve/压缩阈值、知道要重启、背命令。

---

## 一句话总结

> **检测（自动）→ 决策（回一个数字）→ 执行（自动）**。
> 用户不知道 60% 这条规则，也不需要知道；他只需要在技能告诉他"这里可以调"时说一声"好"。
