# 01 · 技能交互流程设计（`context-window-budget`）

- **日期**：2026-09-14
- **状态**：📋 待用户评审（未写代码）
- **用户口径**：每家厂商窗口不同 → 技能运行时应当**根据系统当前已启用的模型，去模型官网取最新上下文大小 → 交用户决策 → 决策后再执行**

---

## 1 设计目标与三条原则

**目标**：把「把 60%/80% 这条最佳实践人工换算成绝对 token 并手改配置」这件事，变成**一次对话**。

**三条原则**

1. **取数不越权**：厂商标称值只作为**证据**呈现，永远由人拍板；技能不自动"相信"任何来源。
2. **决策必须能一句话回完**：默认给决策卡（含推荐项），不让用户读文档做选择题；要细节才展开。
3. **不静默改配置**：默认只读 → 出 patch 预览 → 用户确认 → 才落配置；且永远走 `config.patch`（禁 `config.apply`）。

---

## 2 触发与入口

| 入口 | 说明 |
|---|---|
| 自然语言 | 「更新上下文预算」「检查模型窗口」「模型窗口变了吗」「按 60% 配一下」 |
| 斜杠命令 | `/ctxbudget`（等价可选：`check` / `plan` / `apply` / `rollback` / `audit`） |
| 周期复查 | cron（建议每周一 09:00）→ 只在**检测到变化**时才出声 |

**幂等保证**：重复执行不产生重复写了；已有值与本应值一致时直接报告「无需变更」。

---

## 3 五段式流程总览

```
① 盘点          ② 取数              ③ 出决策卡          ④ 执行            ⑤ 校验+留痕
读 openclaw.json → 官网/官方 API 取窗口 → 推荐值+冲突+影响 → 用户确认 → patch → 重启 → 校验
（已启用模型）      （标来源与置信度）    （一句话可决策）    （可回滚）    （写审计+回滚指令）
                                                            ↕
                                                      ⑥ 周期复查（只报变化）
```

## 4 逐段设计（含示例对话）

### ① 盘点：什么叫"已启用"

**动作**：只读 `openclaw.json`，产出三张清单：

| 分类 | 判定 | 处理 |
|---|---|---|
| **在用** | `agents.list[].model.primary` + `fallbacks`、`agents.defaults.model` | 必进决策卡 |
| **旁路在用** | `agents.defaults.imageModel` / `pdfModel`（如 minimax 图像） | 进决策卡但标「单轮调用」 |
| **已定义未用** | `models.providers.*.models[]` 里没被任何 agent 引用的 | 折叠展示，问是否一并配 |
| **运行时注入** | 插件动态设定的模型（本机有 `nexu-runtime-model`） | **特别标注**，因为它的窗口来源不由配置决定 |

**输出示例**

> 📋 盘点完成：2 家厂商 / 9 个模型
> · 在用（主力）：`deepseek/deepseek-flash`（7 个 agent 全部在用）
> · 已定义未用：`deepseek/deepseek-v4-pro`
> · 旁路在用（图像/PDF）：`minimax/MiniMax-M3`
> · ⚠ 运行时注入：`nexu-runtime-model` 每轮会覆写生效模型，需确认窗口以哪个为准
> 继续取官网数据？（约 30–60 秒，会联网）

*（这一步先问一次，是因为联网取数慢；用户说"直接来"就跳过。）*

### ② 取数：从模型官网拿"最新上下文大小"

**来源优先级**（每一条都记来源与时间，写进 `vendors.json`）：

| 级别 | 来源 | 处理 |
|---|---|---|
| **L1** | 厂商官方文档 / 官方 API 返回的模型元数据 | 直接用，标 URL + 抓取时间 |
| **L2** | 官方控制台/定价页/公告（非模型页） | 用，标注来源类型 |
| **L3** | 第三方汇总 / 社区 | 仅作参考，标「需确认」 |
| **L0** | **用户口述**（如这次的 "deepseek 官网 1M"） | 用，标「用户提供，未溯源」，并请顺手给个链接 |
| **L4** | 当前配置里的值 | 只作兜底；**若与 L1 冲突 → 标红**（本次 `500000` vs `1M` 就是活例） |

**抓取失败降级链**：官方页 → 官方镜像域（经验：部分站点直连不通可用镜像）→ 让用户贴链接/数字 → 标「未溯源」。
**绝不**：抓不到就静默沿用旧值。

**输出示例**

> 🔎 取数结果（2026-09-14 11:5x）
> · `deepseek-flash` → **1,000,000** ▸ L1 官网（`platform.deepseek.com/...`，抓取 11:52）
> · `minimax/MiniMax-M3` → **200,000** ▸ L1 官网（`platform.minimaxi.com/...`，抓取 11:53）
> · ⚠ 与本机现状冲突：`deepseek` 配置里是 **500,000**（用户手填，无来源）→ 建议以 1M 为准
> · ⚠ 缺口：`deepseek-v4-pro` 官网未标 → 请贴链接，或沿用与 flash 同值的假设

---

### ③ 决策卡（核心交互件）

**必须包含 6 个字段**：模型 / 厂商标称（+来源级别） / 建议 cap / 建议 reserve / 现状值 / 变化方向。

**决策卡的推荐值算式**（比例可改）：`cap = 60% × 窗口`，`reserve = 20% × cap`，`floor = reserve` → 触发点 = cap 的 80%。

**输出示例（真实形态，短版）**

> 🎛️ **上下文预算 · 决策卡**（比例：cap 60% × 窗口 ｜ 触发 80% × cap）
>
> **1. deepseek-flash**（在用 · 7 agents）
> 　标称 1,000,000 ▸ L1 ｜ 建议 cap **600,000** ｜ reserve **120,000** ｜ 触发点 **480,000**
> 　现状 cap 500,000 / reserve 20,000 → 触发点 480,000（= 96% 窗口，几乎无注意力保护）
> 　变化：cap 更宽（+100k），但**触发点更早生效**（相对 cap 从 96% → 80%）
>
> **2. minimax/MiniMax-M3**（图像，单轮调用）
> 　标称 200,000 ▸ L1 ｜ 建议 cap **120,000** ｜ reserve **120,000**（受全局冲突，见下）
>
> ⚠️ **需要你选一项：reserve 是全局唯一值，两模型无法同时精确**
> 　**① 主力优先**（推荐）：reserve = 120,000 → minimax 会在 80k 就压缩（偏高但安全）
> 　**② 小窗口优先**：reserve = 24,000 → main 主力要到 92% 才压缩（= 放弃注意力保护）
> 　**③ 切换重算**：切模型时自动重跑本技能改 reserve（多一步动作，最精确）
>
> 回复示例：`1①` ｜ 想改比例回 `改比例 0.5/0.8` ｜ 只想先看 diff 回 `看patch` ｜ 取消回 `算了`

**设计要求**
- **默认短卡**：只展示会变的和要决策的；其余折叠（回 `看全部` 展开）。
- **变化方向必须写清**：cap 变大 ≠ 压缩变晚（本次就是反例），否则用户会误判。
- **冲突单独列块**，不藏在表格里。
- **决策粒度**：cap 可按模型单独勾选；**reserve 只能单选**（硬约束，必须显式教育用户）。
- ⚠️ **每个模型必须并排两列**（2026-09-14 用户指出后新增）：
  - **「公式本意」**：cap = 60%×窗口，reserve = 20%×cap → 触发点 = 80%×cap
  - **「本机可执行」**：受**全局唯一 reserve** 约束后的真实触发点 = cap − 实际 reserve
  例（M2.x 窗口 204,800）：公式本意 cap 122,880 / reserve 24,576 / 触发 **98,304**；本机可执行（reserve 被设成 120,000）触发 **2,880** ✗
  **只写一个数会让人以为算错了** —— 这两个数必须同时出现，并说明分叉原因。

### ④ 执行（用户确认后）

固定 6 步，全程可回滚：

| 步 | 动作 | 失败处理 |
|---|---|---|
| 1 | **改前快照**（供回退用，不留痕、不编号） | 失败即中止（无快照不动配置） |
| 2 | **前置校验**：cap ≥ 16k（源码 hard min，低于会被拒）；< 32k 警告；`cap − reserve > 0`（否则每轮压缩=灾难）；比例 ∈ [0.1, 0.9] | 不通过 → 拒绝执行并说明 |
| 3 | **落配置**：`config.patch`（**永不 `config.apply`**），只写被决策的键 | 校验失败 → 回退 |
| 4 | **重启**：`config.patch` 只做就地重载，**必须再 restart** 才能刷新生成的 Pi 模型目录 | 重启失败 → 报错并保留快照 |
| 5 | **清显示缓存**：删会话存储里过期的 `contextTokens`（先备份 `sessions.json`） | 失败 → 只是显示滞后，标注即可 |
| 6 | **校验**：`/status` 显示窗口 + 生成的 `agent/models.json` 值 + 触发点复核 | 不一致 → 报差异，不谎报成功 |

**输出示例**

> ✅ 已执行（审计 `ctx-20260914-1158`）
> · `models.providers.deepseek.models[].contextWindow` 500000 → **600000**
> · `agents.defaults.compaction.reserveTokens` 未设 → **120000**
> · `agents.defaults.compaction.reserveTokensFloor` 未设 → **120000**
> · 重启 ✅ ／ 会话缓存清理 ✅
> · 校验：`/status` = `200k/600k (33%)` ✅ ｜ Pi models.json = 600000 ✅ ｜ 触发点 480,000（cap 80%）
> · 回滚：回 `回滚 ctx-20260914-1158`（备份 `tmp/openclaw.json.bak-…`）

### ⑤ 校验（**不留痕**）

- **校验**：`/status` 显示窗口 + 生成的 `agent/models.json` 值 + 触发点复核
- **不留痕**（用户 2026-09-14 12:11 定）：**不写审计文件、不记录修改历史、不生成历史清单**
- `vendors.json` 仅作**厂商标称值缓存**（用于减少联网），不含"谁在何时改过什么"的记录
- **回退**：直接还原「改前快照」→ 重载 → 校验（无编号、无历史依赖）

### ⑥ 周期复查（可选 cron，建议每周一）

- 只做 ① 盘点 + ② 取数 + 差异比对
- **有变化才出声**（例：deepseek 标称从 1M → 2M，或新增模型落回 200k 兜底）
- 无变化 → 静默（`NO_REPLY`），不刷屏

## 5 数据契约：`vendors.json`

```jsonc
{
  "deepseek": {
    "models": {
      "deepseek-flash":  { "window": 1000000, "level": "L1", "source": "https://...", "collected_at": "2026-09-14", "note": "" },
      "deepseek-v4-pro": { "window": null,    "level": "gap", "source": null,        "collected_at": null,        "note": "官网未标，待补" }
    }
  },
  "minimax": { "models": { "MiniMax-M3": { "window": 200000, "level": "L1", "source": "https://...", "collected_at": "2026-09-14" } } }
}
```

- **唯一真源**：厂商标称窗口只在这里；配置里的 `contextWindow` 是"算完的结果"，不是源头。
- **必须带来源与时间**：杜绝本机 `500000` 这种"无从溯源"的数字（那正是这次问题的起点）。

---

## 6 边界与拒绝条件（防呆）

| 情形 | 处理 |
|---|---|
| `cap ≤ reserve` | **拒绝执行**（阈值 ≤ 0 → 每轮压缩，任务直接废） |
| `cap < 16k` | 拒绝（源码 hard min 会 block） |
| `cap < 32k` | 警告后放行 |
| 厂商标称 < 配置现值 | 标红并复述差异，请用户二次确认（可能是配置填错，也可能是厂商缩水） |
| 官网抓不到 | 降级 → 用户口述/沿用现值并标「未溯源」，**不静默通过** |
| 运行时注入模型 | 提示"窗口可能不由本配置决定"，建议以实测为准 |
| 多厂商异构 | 强制走 ③ 的 reserve 三选一，不允许默默取平均 |
