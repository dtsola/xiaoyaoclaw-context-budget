## 2 触发词：以「上下文检查 / 上下文优化」为明确主词

### 主触发词（首选，显式表达）

> **「上下文检查」** / **「上下文优化」**（核心目的 = 上下文优化）

变体（同义，均应触发）：

| 类型 | 说法 |
|---|---|
| 标准 | 上下文检查 / 上下文优化 / 检查上下文 / 优化上下文 / 上下文窗口检查 / 上下文体检 |
| 加对象 | 检查一下模型上下文 / 优化一下模型上下文 / 检查上下文窗口 / 上下文大小检查 |
| 加目的 | 上下文检查一下 / 帮我做次上下文检查 / 优化我的上下文配置 / 看看上下文大小 |
| 带动作 | 把上下文按最佳实践配一下 / 检查并设置上下文窗口 |

**判定规则（简化且明确）**：**出现「上下文」+（检查 / 优化 / 体检 / 查 / 看看）→ 触发**。

### 其它仍应触发的场景（非"检查"句式）

| 场景 | 示例 | 处理 |
|---|---|---|
| 新增/更换模型 | 「我加了个 kimi，把窗口配上」「换模型了，上下文配一下」 | 只针对新模型检测 |
| 质疑配置 | 「上下文窗口是不是太小了」 | 先检测再给结论，不直接改 |
| 直接下命令 | `/xiaoyaoclaw-context-budget` | 等价「上下文检查」 |

## 3 反触发清单（写进 description，防误触发）

| 反例 | 原因 | 归属 |
|---|---|---|
| 「什么是上下文窗口」 | 纯知识问答 | 直接解释，不动配置 |
| 「帮我整理记忆 / 压缩上下文」 | 记忆蒸馏 | `xiaoyaoclaw-memory-distill` |
| 「今天 token 用了多少」 | 用量统计 | `xiaoyaoclaw-usage-report` |
| 「上下文溢出了怎么办」 | 排障咨询 | 解释 + 建议 |
| 只说「上下文」 | 太宽泛 | **不触发**（必须带检查/体检类动词或明确配置意图） |
| 「先别改配置」 | 显式禁止 | 只读检测 |

## 4 子指令（自然语言，不改命令长度）

| 用户说 | 行为 |
|---|---|
| 上下文检查 / 上下文优化 | 默认 = 检测（零改动） |
| 上下文检查 撤销 / 撤销上次上下文调整 | 回滚到改动前的配置（**无历史清单**） |
| 上下文检查 全量 | 含"已定义未在用"的模型 + 官网漂移巡检 |

> **不做 `/apply` 类静默执行** —— 执行必须由决策卡后的确认触发。
> **不做历史/审计**（用户 12:11 定）：不记录修改历史、不写审计文件。

## 5 SKILL.md description 建议文本（模型触发依据）

```yaml
name: xiaoyaoclaw-context-budget
description: 上下文检查 / 上下文优化（OpenClaw 模型窗口预算）。核心目的 = 上下文优化：
  检测系统当前「已启用模型」的上下文窗口，到各模型官方来源取最新标称值，按 60% 给出建议窗口，
  用户确认后写入配置并校验。
  主触发词：上下文检查、上下文优化；同义说法：检查上下文、优化上下文、上下文窗口检查、上下文体检、
  检查一下模型上下文、上下文大小要不要调、把上下文窗口配一下。新增或更换模型后要求配置窗口时同样触发。
  不做：maxTokens 等其它参数、压缩阈值、未在用模型的默认配置。
  英文关键词：context window check, context optimization, context budget, model context size。
disable-model-invocation: false
user-invocable: true
```
