# OpenClaw Context Budget · 设计文档

> 项目：`xiaoyaoclaw-context-budget`｜标题：**OpenClaw Context Budget**
> 一句话：把「模型上下文窗口该配多大」变成**一次检测 + 一个数字确认**。

---

## 一、背景与问题

各家模型的上下文窗口差别很大（200K / 1M…），而 OpenClaw 在模型未显式声明窗口时，会退回一个**兜底默认值**（源码常量 `DEFAULT_CONTEXT_TOKENS = 200000`）。由此产生三类问题：

| 问题 | 现象 | 根因 |
|---|---|---|
| 窗口被低估 | 上下文被**过早自动摘要**、长任务被打断、压缩时卡顿 | 模型未声明窗口 → 落回 200k 兜底，触发点过低 |
| 窗口被高估 | 模型在超长上下文里**注意力分散**、回答质量下降 | 配置里手填的窗口值缺少依据（无来源、无换算） |
| 配置无从溯源 | 配置里写着 `500000` 之类的数字，没人知道依据 | 缺少「厂商标称窗口」的唯一真源与采集记录 |

**结论**：缺的不是"能不能改"，而是**比例语义**与**按模型取值**这两件事需要人工完成。

---

## 二、机制事实（OpenClaw 2026.3.7 源码取证）

### 2.1 上下文窗口解析链（`src/agents/context.ts` → `resolveContextWindowInfo`）

1. `models.providers.<provider>.models[].contextWindow`（**配置覆写，最高优先**）
2. 模型注册表里的 `contextWindow`
3. 兜底 `DEFAULT_CONTEXT_TOKENS = 200000`
4. 若 `agents.defaults.contextTokens` 更小，则用它下压

### 2.2 自动摘要（压缩）触发条件（Pi 运行时语义）

```
触发：  contextTokens > 有效窗口 − reserveTokens
其中：  reserveTokens = max(配置值 或 Pi 默认 16384, reserveTokensFloor 默认 20000)
记忆落盘(memoryFlush)阈值 = 有效窗口 − reserveTokensFloor − softThresholdTokens(4000)
```

### 2.3 能力边界（schema 实证，决定方案形态）

| 能力 | 是否支持 |
|---|---|
| 按模型设置窗口（`models.providers.*.models[].contextWindow`） | ✅ |
| 全局压顶（`agents.defaults.contextTokens`） | ✅ |
| 按 agent 覆盖窗口 / 压缩设置（`agents.list[].contextTokens` / `.compaction`） | ❌ **不存在** |
| 任何"按比例"的压缩阈值字段（如 `compactAtRatio`） | ❌ **不存在** |

**推论**：`reserveTokens` 是**全局唯一**值 → 「每个模型都精确 80% 触发」做不到；要避免该冲突，最稳的路径是**不改压缩阈值（用默认），只用窗口值做注意力保护**。

## 三、设计口径（项目宪法）

| # | 口径 | 来源 |
|---|---|---|
| 1 | **有效窗口 = 厂商标称窗口 × 60%**（留余量，减少注意力分散） | 用户最佳实践 |
| 2 | **压缩阈值保持系统默认，不碰** | 用户 2026-09-14 12:00 |
| 3 | **只配置「已启用」模型**（在用 + 图像/PDF 这类旁路在用）；未在用模型默认不动 | 用户 12:00 |
| 4 | 只做窗口大小；`maxTokens`、成本、并发等**一律不碰** | 用户 12:02 |
| 5 | 用户流程 = **检测（只读）→ 决策（回一个数字）→ 执行（确认后写入）** | 用户 12:11（措辞按 ClawScan 复核收窄） |
| 6 | **不留痕**：不写审计文件、不记录修改历史、无历史清单 | 用户 12:11 |
| 7 | 60% 是**技能内部默认**，不作为用户输入项（用户不需要知道这条规则） | 用户 12:04 |
| 8 | 改动必须经用户确认；**不存在静默改配置的路径** | 安全要求 |
| 9 | 改配置一律 `config.patch`，**禁用 `config.apply`** | 多 agent 共享配置铁律 |

**60% 的语义澄清**：它保护的是**模型注意力**，不是机械安全余量（示例：某环境 `maxTokens` 仅 8192，机械余量远小于 40%）。因此**不要**把这条比例理解为"留出溢出空间"。

## 三之二、通用性要求（用户 2026-09-14 12:21 定）

技能必须**同时适用于 OpenClaw 与 小遥Claw（桌面版，内嵌 OpenClaw runtime）**及各类安装形态：

| 要求 | 做法 |
|---|---|
| 不硬编码安装路径 | 配置读写首选 agent 的 gateway 工具（`config.get` / `config.patch`）；不可用时按平台常见位置探测（标准安装 `~/.openclaw/`、桌面版内嵌 runtime 的 state 目录），或询问用户 |
| 不硬编码模型名 | 模型清单**运行时从配置枚举**（`models.providers.*.models[]` + 各 agent 的 model/imageModel/pdfModel 引用） |
| 不硬编码窗口数值 | 厂商标称窗口每次运行**联网检索官方来源**（无本地数据表、无缓存、不沿用旧值） |
| 不假设运行态数值 | 校验读运行态（`/status`）；不写死任何数字 |
| 不假设生效机制 | 配置写入后按该形态实际机制重载/重启；以实测为准 |
| 文档示例仅作示例 | 任何出现的模型名/数值都必须可被运行时结果替换 |

## 四、三段式流程

```
① 检测（只读）    读配置盘点在用模型 → 去官网取最新标称窗口 → 比对现状 → 算 60% 建议值
      ├─ 无差异 → 一句话结束
      └─ 有差异 ↓
② 决策（一个数字） 用户回 1 采纳 / 2 保持 / 3 看详情
③ 执行（确认后写入）  记旧值 → 前置校验 → config.patch → 提示重载（不擅自执行） → 校验 → 回执
```

### 执行段固定 6 步（范围已按 ClawScan 复核意见收窄）

| 步 | 动作 | 失败处理 |
|---|---|---|
| 1 | 记录**本次将被修改字段的旧值**（一次性、覆盖式；供一步回退） | 失败即中止 |
| 2 | 前置校验：`cap ≥ 16000`（源码 hard min）；`cap < 32000` 警告；`cap − 默认 reserve > 0`；比例 ∈ [0.1, 0.9] | 不通过 → 拒绝并说明 |
| 3 | `config.patch`：只写被决策的窗口键 | 校验失败 → 回退旧值 |
| 4 | **提示重载/重启**（说明需要它才会刷新运行态模型元数据，并给出建议命令）；**不擅自执行**，仅用户明确要求时代为操作 | 失败 → 报错并保留旧值 |
| 5 | **会话状态：不处理**（用户反馈显示滞后时只解释"这是显示缓存、配置已生效"，交由用户自行处置；**本技能不修改会话存储、不生成备份文件**） | 不适用（不改动即无失败面） |
| 6 | 校验：`/status` 窗口值 + 生成的 `agent/models.json` + 触发点复核 | 不一致 → 如实报差异 |

> ⚠️ **权限边界（复核后定稿）**：不擅自重启、不擅自清理会话状态、不创建定时任务；写入前必须用户确认。

## 五、触发词

- **主触发词**：`上下文检查`（同义：检查上下文 / 上下文窗口检查 / 上下文体检 / 检查一下模型上下文）
- **判定**：出现「上下文」+「检查/体检/查/看看」即触发
- **场景触发**：新增或更换模型后要求配置窗口；质疑窗口大小时（先检测、不直接改）
- **命令**：`/xiaoyaoclaw-context-budget`
- **反触发**：什么是上下文窗口（纯问答）／整理记忆（归 memory-distill）／token 用量（归 usage-report）／只说"上下文"／用户说"先别改配置"

详见 `docs/TRIGGERS.md`。

## 六、信息来源与可信度分级

| 级别 | 来源 | 处理 |
|---|---|---|
| **L1** | 厂商官方文档 / 官方 API 模型元数据 | 直接采用，标 URL + 抓取时间 |
| **L2** | 官方控制台 / 定价页 / 公告 | 采用，标注来源类型 |
| **L3** | 第三方汇总 / 社区 | 仅参考，标"需确认" |
| **L0** | 用户口述 | 采用并标"未溯源"，请其补链接 |
| **L4** | 当前配置值 | 只作兜底；与 L1 冲突时**标红复核** |

抓取失败降级链：官方页 → 官方镜像域 → 请用户贴链接 → 标"未溯源"。**绝不静默沿用旧值。**

## 七、边界与拒绝条件

| 情形 | 处理 |
|---|---|
| `cap ≤ 默认 reserve`（阈值 ≤ 0，会导致每轮摘要） | **拒绝执行** |
| `cap < 16000` | 拒绝（源码 hard min） |
| `cap < 32000` | 警告后放行 |
| 官网标称 < 配置现值 | 标红复述差异，请用户二次确认 |
| 官网取不到 | 请用户给链接或按现状跳过（标未溯源） |
| 多厂商窗口异构 | **无冲突**（压缩用默认），各模型 cap 独立 |
| 运行时注入模型（如平台插件覆写生效模型） | 标注"窗口可能不由本配置决定" |

## 十、实现形态：纯指令式（用户 2026-09-14 12:17 定）

- **不含脚本**、**不含本地数据文件**（曾实现过的 `scripts/ctxbudget.py` 与 `scripts/vendors.json` 已按用户口径移除）
- 原因：技能本质是指令集，全流程用内置工具即可完成；文件/脚本会带来**维护成本**（厂商标称会变，数据文件必然过期）与**运行时依赖**（Python / 跨平台编码）
- 改为：**运行时动态联网取数**（每次检测去官网取最新标称），来源与抓取时间只在决策卡上呈现

**必须写进指令的硬规则（原脚本承担的防错，改为自检清单）**

1. 载荷必须带该 provider 的**完整 `models` 数组**（`models` 在 `config.patch` 中是数组整体替换，少一个即误删）
2. 自检数组长度与 id 列表，仅目标模型 `contextWindow` 变化
3. 数值校验：`cap ≥ 16000`；`cap < 32000` 告警；`cap − 默认 reserve(20000) > 0`；比例 ∈ [0.1, 0.9]
4. 只写窗口字段；`gateway config.patch`（禁 `config.apply`）

**代价（已知并接受）**：每次检测都需联网取数（约 30–60 秒），无离线可用性；取数失败时走降级链而不是读本地缓存。
